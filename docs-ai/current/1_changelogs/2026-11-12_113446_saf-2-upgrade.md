# SAF 2.0.0 major upgrade

- Record opened: 2026-11-12 11:34:46, America/Sao_Paulo (UTC-03:00).
- Baseline: `c89cf42b28b6ea540c4b109f614e016971d7eb32`, with earlier analysis/audit edits preserved.
- Release: `2.0.0`, an explicitly requested breaking major version. Local implementation is prepared; no Git commit, tag, push, repository rename, or remote publication was performed.

## Implemented behavior

Replaced `fetch-agents.bat` and its controller with repository-local `origin.bat` / `scripts/origin.ps1`. Check reports availability/conflicts, Update applies a release, and Sync checks then updates from one resolved Git snapshot. No arguments select Sync; explicit actions skip waits. Force requires Update and preserves project-owned seeds. Daily synchronization reads remote data without executing an independently moving remote controller. Unsupported handler contracts return a bootstrap-refresh result.

Added source-only `init.ps1` for remote PowerShell evaluation or named script parameters. It validates one source commit, stages the complete five-file handler set, backs up replaced files, adds local runtime ignore rules, and writes bootstrap state last. It does not install the full payload or complete an audit. Reinitialization replaces the known handler set, including PS1 helpers, rather than depend on historical installer handoff. The configured repository remains `Evigila/AGENTS.md` pending a separately published rename.

Added `local.bat` / `scripts/local.ps1` for scoped backups, verified ZIP archive export/cleanup, and idempotent ignore rules. Retained `arquived` spelling and added correctly spelled aliases. Archive exports include hidden files and hashes, are reopened/verified, and clean only unchanged exported content. New/changed files and recovery/cleanup failures are reported. Downloads uses the current user's redirected Windows folder setting, with an explicit destination option. Existing tracked archives remain tracked after ignore configuration; cleanup creates unstaged deletion differences, never a commit or push.

Renamed the seeded project entry point to `debug.bat` and made the publication slot generic (`scripts/publish-package`). Preserved nonempty legacy debug bytes during consumer migration, with a conflict if two different project menus exist. No actual debug/database/publication implementations are supplied by the framework.

## State, skills, and standards

Replaced `AGENTS.framework.json` with `SAF.json`. Installation and audit metadata now use independent `bootstrap`, `installation`, and `audit` sections in `SAF.lock.json`; central source bootstrap/installation remain null. Legacy metadata is imported with exact baselines and genuine audit timestamps, and retired only through validated migration. Shared operation leases and read/merge/atomic-write helpers protect cooperating state writers. Updates preserve audit evidence; a release-version mismatch requires the separate documentation audit.

Renamed `sync-agents-framework` to `sync-saf`, adapted `audit-project-docs`, and added `compress-saf`. Per user clarification, audit and semantic compression are skills only, not local BAT commands. Compression preserves complete inventories, effective constraints, provenance, unresolved work, human ownership, changelogs, and bug evidence.

Updated the router, shared contracts, consumer templates, source inventories, publisher, and CI for SAF. Removed mandatory Arkheide namespace, Flourish UI, and NuGet ecosystem assumptions. New local storage is `.agent/backup/`, `.agent/saf_log/`, and `.agent/operation.lock`, distinct from `.agents/skills/`. Init/origin/local append operational completion records with operation ID and UTC start/end; Check permits log-only writes, never payload/manifest/lock writes.
